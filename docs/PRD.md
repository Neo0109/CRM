# Sourcing CRM PRD

## 目标

为 B站游戏发行 BD 搭建围绕 sourcing 的轻量 CRM，通过 Codex 和自动化任务完成每日扫描、结构化 leads 生成、池子分配、CRM 写入和人工筛选推进。

系统服务的是“前置发现 + 大漏斗筛选 + 正式推进”，不是传统销售 CRM。

## 设计原则

- 尽可能早地发现前期线索。
- 从线索池中持续筛出值得投入 BD 时间的项目。
- 国内项目优先。
- 海外项目只保留画面足够讨喜或已有公开强数据的项目。
- 排除 PC Early Access、叙事主导、印度团队。
- 已有成熟发行商且中国能力已占位的项目降权或淘汰。
- 口碑过低、窗口太晚的项目直接淘汰。

## 漏斗

- 原始情报池：自动扫描得到的全部候选。
- 观察池：方向对，但还缺强信号。
- 推进池：值得花真实 BD 时间。
- 淘汰池：统一淘汰标准，避免重复讨论。

## 用户

- Neo / B站游戏发行 BD 负责人：浏览、筛选、标记优先级、补充商务判断、推进对接。
- BD Ops：补充资料、维护动作闭环、更新 Owner / Due Date。
- 评测 / 测试负责人：填写产品验证与风险结论。
- 内容 / 编辑：填写 B站适配与内容放大方案。

## 必要模块

### Leads 列表页

- 搜索项目名、团队、类型、关键词。
- 过滤推进池、观察池、淘汰池。
- 过滤国内 / 海外。
- 过滤阶段、Owner、发售窗口。
- 快速查看项目名、团队、类型、进度、发行结构、公开信号、下一步动作。

### Lead 详情页

- B站适配度。
- 放大作用。
- 已有发行商与中国能力是否占位。
- 前置曝光轨迹。
- 风险结论。
- 下一步动作。

### 导入

- 支持从每日扫描结果 JSON 自动写入。
- 支持人工粘贴 JSON 导入。
- 支持同项目名 + Steam AppID / 官网链接去重。

### 导出

- 导出 JSON。
- 导出 CSV。
- 后续可扩展到 Airtable / Notion / Supabase。

## 成功标准

- 原始线索池显著扩大。
- 正式推进池质量提升。
- 更早发现适合 B站 的项目。
- 减少“已经太晚 / 已被占位”的无效项目。
- CRM 可筛选、可导入、可导出。
- 推进池 / 观察池 / 淘汰池清晰可见。
- 曝光轨迹可复盘。
