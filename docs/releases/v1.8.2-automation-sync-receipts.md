# v1.8.2 Automation Sync Receipts

## Summary

Adds a persistent online receipt for every daily CRM automation run so the team can tell whether the run generated data and whether the CRM sync endpoint confirmed success.

## Changes

- Resolve an explicit run slot for each automation run:
  - `morning` for 09:30 Asia/Shanghai schedule.
  - `afternoon` for 14:00 Asia/Shanghai schedule.
  - `manual` or a custom slot for workflow dispatch.
- Keep generating the canonical daily files:
  - `data/reports/YYYY-MM-DD.json`
  - `data/radar/YYYY-MM-DD.json`
  - `data/steam_trends/YYYY-MM-DD.json`
- Write a sync receipt after CRM sync:
  - `data/automation_runs/YYYY-MM-DD-slot.json`
- The receipt stores generation status, sync status, retry count, GitHub run URL, trigger type, schedule, timestamp, and the CRM sync response.
- If CRM sync does not return `"synced": true`, the workflow records the receipt and then fails the run, making the failure visible while preserving debugging evidence.

## Diagnosis From 2026-05-28

The online automation generated today's files multiple times. The visible confusion came from the current design writing the morning and afternoon runs into the same canonical daily files, so the app shows one latest daily state rather than two separate report cards.

## Follow-Up

If the product should show AM/PM as separate report batches in the UI, add batch-aware report history and a visible automation status panel. This v1.8.2 change intentionally stays small and only adds reliable traceability.
