# v2.3.1 Daily Automation Quality Guard

Date: 2026-06-02

## Changes

- Added a protected CRM dedupe-index endpoint for cloud automation so daily generation can filter against production CRM leads, not only recent report files.
- Updated the daily generator to accept an external dedupe index and exclude existing production projects by project name and Steam AppID before filling candidate pools.
- Added detailed import stats to daily-report sync results, including newly created unprocessed leads, visible unprocessed updates, dropped imports, and stale updates.
- Added GitHub Actions quality gates that fail a daily run when CRM sync succeeds but newly created unprocessed leads are below the useful threshold.
- Updated the watchdog to understand import-quality stats so a report with files and a successful sync receipt can still be marked unhealthy when it produces too few new actionable leads.

## Why

The 2026-06-02 recovery run generated 26 report candidates, but the CRM sync response showed `created=4` and `updated=22`. Most candidates were existing production leads, so they did not appear as new unprocessed work. The old automation only validated report shape and source counts; it did not validate whether the sync produced enough new actionable leads.
