# v2.0 BD Efficiency Workflow

## Changes

- Bumped the visible CRM version and health endpoint from `v1.10` to `v2.0`.
- Replaced the homepage evidence-gap lane with a testing-first workflow: `未处理` -> `先测游戏` -> `测过再商务`.
- Clarified that missing contacts or websites should not block first-pass game testing.
- Updated Sourcing V4 rules so domestic unreleased products are not hard-dropped merely because the launch window is under 60 days.
- Expanded the online daily generator with more China-locale Steam discovery surfaces for strategy, simulation, co-op, roguelike, and deckbuilder candidates.

## Product Rationale

The CRM should reduce BD workload. New automated leads should first help the BD owner decide whether the game is worth testing. If testing fails, the project should be dropped quickly instead of requiring extra contact or evidence completion.
