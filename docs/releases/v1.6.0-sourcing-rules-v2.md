# v1.6.0 Sourcing Rules V2 Automation

Date: 2026-05-26

## What Changed

- Added `docs/SOURCING_RULES_V2.md` as the daily report standard.
- Added `automations/jobs/online_daily_v4.mjs` using Sourcing Rules V2.
- Updated the daily GitHub Actions workflow to call the V2 generator.
- Added a 14:00 Asia/Shanghai GitHub Actions retry/new-batch schedule, in addition to the 09:30 primary run.
- Made CRM sync stricter: the workflow now retries sync and fails unless the CRM endpoint confirms `synced=true`.
- Updated `/api/health` to expose `v1.6.0-sourcing-rules-v2`.

## Product Logic

The generator no longer treats “popular upcoming” as an automatic push recommendation. It separates discovery from BD recommendation:

- Push pool can be empty and is no longer force-filled.
- Near-launch projects, including games launching within 60 days, do not enter push pool by default.
- PC Early Access, narrative-heavy projects, India-led teams, and mature-publisher-occupied projects are dropped or heavily downgraded.
- Watch pool is the broad funnel for early signals.
- Drop pool records the reason so the team does not reopen the same discussion.

## Why This Fix Was Needed

The previous v3 automation accidentally removed the `releaseTooSoon` exclusion from push classification, so projects launching in one or two days could appear in the push pool. That violated the Sourcing V2 goal: early, accurate, and still actionable.

## Automation Diagnosis

The repository workflow previously had only a 09:30 Asia/Shanghai schedule. The 14:00 run the user expected was not represented as a GitHub Actions schedule. In addition, the CRM sync step only checked for `error`; if GitHub raw JSON had not refreshed yet and the endpoint returned `synced=false`, the workflow could appear to continue without a confirmed CRM import.

v1.6.0 fixes both issues by adding the 14:00 GitHub Actions schedule and requiring `synced=true` after retries.
