# v2.0.1 Frontend Entrypoint Fix

## Changes

- Fixed the Cloudflare Pages entry functions that still referenced old `v1.10` jsDelivr asset hashes.
- Changed the frontend build output to stable `assets/index.js` and `assets/index.css` names so future builds do not require manual entrypoint hash updates.
- Kept the product-visible version at `v2.0`.

## Root Cause

The API and data pipeline were deployed to `v2.0`, but the Pages HTML function was still hardcoded to old frontend bundle filenames. The browser therefore loaded the previous UI even though `/api/health` already reported the new version.
