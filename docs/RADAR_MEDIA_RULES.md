# Industry Radar media rules

Machine configuration: automations/rules/daily-report.json (radar_diversity and radar_sources). Collection/selection: automations/jobs/online_daily_v4_radar.mjs. Pure editorial rules and bilingual event aliases: automations/jobs/online_daily_v4_radar_editorial.mjs. Entry remains the normal Daily V4 generator.

- Every publisher passes the same game-relevance assessment. Direct game products, gameplay, demos, trailers, reviews, updates, engines and game-industry events lead. Hardware and adaptations require explicit game context; unrelated film/TV and generic technology do not qualify. Publisher names, inherited Lead scores and generated card boilerplate are not relevance evidence.
- The collector optionally provides a deep-copied Radar snapshot after source enrichment and before Lead filters. Lead return values, admission, diagnostics and Steam processing remain unchanged. Radar scores only its independent copies.
- Rank by relevance, publication within 24h, information plus source credibility, then publication timestamp. The regional 16/16 fill targets are removed. The 30–40 target remains subject to hard caps: 40 external, 3/media, 12/topic, 24/publisher region, and 3 total Bilibili. No cap-bypassing filler. Internal Steam direction card counts separately.
- Publication must be known, not future, and no older than 72h. Missing dates use publisher JSON-LD/meta/time evidence. Domestic articles needing dates or original-source attribution get priority within existing metadata request limits.
- Group before choosing representatives. Normalized URL/title and explicit original-article attribution are strongest evidence. Otherwise use maintained bilingual entities, matching event action and distinctive facts. Conflicting dates/versions/chapters, different progress and independent reviews remain separate; uncertain matches are retained.
- Prefer domestic coverage only if its summary is substantive and it retains key dated/versioned facts. Domestic identity is registered publisher name/domain, not a story mentioning China. Try other complete domestic coverage when a cap is exhausted, then qualified foreign coverage. Keep each representative's own title, summary and link; do not attach foreign claims to domestic attribution.
- Apply URL/title, article-event and video-event suppression to the previous seven Shanghai dates. Same-day artifacts are excluded. Historical cards are assessed from their own saved text; missing citation evidence is never invented.
- Added network calls stay within four workers, 8s/request, 60 article metadata requests and the 90s total deadline. No new search provider, paid AI, credentials or CRM calls. Source failure is isolated. API, cards, categories, UI and scheduled workflow triggers remain unchanged.
- Runtime/workflow diagnostics report relevance levels, publisher regions, unknown/stale/unrelated exclusions, article/video/history duplicate counts, domestic replacements and cap fallbacks, source failures and elapsed request time.

Verification: onlineDailyV4Radar.test.mjs, the Daily suite, schema/typechecks and npm run verify:all. scripts/replay-radar-editorial.mjs replays archived cards with explicitly synthetic publication dates to check curation and same-day behavior; it does not claim to re-verify original freshness. Production acceptance uses the real generated file and a status=success receipt whose parsed sync_response.synced is true. Formal Lead count is not Radar delivery health.
